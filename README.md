# TapCollect

TapCollect（网页信息采集工具）是一款基于 Electron、Vue 3、TypeScript 和 TDesign Vue Next 的跨平台桌面工具。它通过可视化点选或手写选择器采集网页列表与详情信息，再按照用户提供的 XML、XLSX 或 XLS 模板完成字段映射、资源处理和分批导出。

当前版本：`v0.4.8`

## 下载与支持平台

正式安装包可从 [GitHub Releases](https://github.com/CastleInTheSky0/TapCollect/releases) 下载。

| 平台 | 架构 | 产物 |
| --- | --- | --- |
| Windows | x64 | NSIS 安装程序 `.exe` |
| UOS / Linux | ARM64 | Debian 安装包 `.deb` |
| macOS | Intel x64 | `.dmg`、`.zip` |
| macOS | Apple Silicon ARM64 | `.dmg`、`.zip` |

macOS 安装包当前未使用 Apple Developer 证书签名或公证，首次打开时可能出现 Gatekeeper 的未认证开发者提示。

## 功能概览

### 任务管理与运行中心

- 支持新建、复制、编辑和删除多个采集任务，左侧任务栏可折叠。
- 使用五步配置向导：采集入口、列表与分页、详情、模板映射、输出与测试。
- 配置区、字段区和网页预览区支持折叠及拖动调整宽度；运行日志区域支持拖动调整高度。
- 成功、警告和错误提示使用 TDesign 消息组件，默认显示 5 秒，并可手动关闭。
- 正式采集前必须先保存草稿；保存时会逐项列出尚未完成的配置。
- 支持将全部已保存任务导出为一个 JSON 文件，并在其他设备导入。导入时逐个任务校验，无效任务会跳过并显示原因。
- 运行中心支持同时运行多个正式任务，全局并发数可设置为 1–5，默认 3。
- 超出并发数量的任务自动排队；写入同一输出目录的任务会等待目录锁释放，避免互相覆盖。
- 支持单任务及全部任务的暂停、继续和取消，并显示当前页面、成功/失败数量、资源下载数量和运行时间。
- 实时日志会记录正在采集的记录及链接，单个任务在本次会话中保留最近 500 条日志。
- 测试采集处理前 3 条记录，不占用正式任务并发名额，也不会实际下载资源；测试完成后可按当前 XML/XLSX/XLS 模板导出测试文件，实地验证最终文件格式。
- 删除任务会同步清理任务配置、检查点和运行中心记录，但不会删除已生成的 XML、表格、附件或其他输出文件。

### 网页预览、点选与选择器

- 内置隔离网页预览，支持打开列表页与详情页。
- 支持悬停高亮、鼠标点选生成选择器、匹配数量验证和示例值回显。
- 支持 CSS 与 XPath 1.0，可直接手动编辑选择器。
- 自动生成的 CSS 选择器从最近的唯一 ID 祖先（没有时从 `body`）开始，用 `>` 保留到目标节点之间的每一级；各级优先使用 ID、class，重复 ID 会与祖先路径组合，尽量避免易受节点顺序影响的 `:nth-of-type(...)`。
- 列表项只需选择一条完整记录的范围节点，例如 `ul` 下重复的 `li`、`.content-list` 下重复的 `.content-item`。
- 字段选择器相对于列表项范围执行，便于准确采集同一列中的每条记录。
- 详情链接点选可识别列表项内部链接、列表项自身为 `<a>`，以及 `<a>` 包裹列表项的结构。
- 预览工具栏支持后退和前进；打开列表、进入详情或页内跳转时会同步导航历史。
- 打开预览和详情时显示加载蒙层并防止重复操作，加载完成或失败后恢复操作。

### 列表地址与分页

支持无需分页、静态地址分页和动态点击分页三种常见场景。

静态地址模式：

- 列表页面 URL 使用多行输入框，每行一条，固定地址会按填写顺序各采集一次。
- 同一任务可混合多条固定地址和一条 `{page}` 数字分页模板。
- `{page}` 可位于查询参数、路径或文件名中，例如：

```text
https://www.example.com/list.html
https://www.example.com/list_{page}.html
https://www.example.com/list.aspx?classid=5&page={page}
```

- 可设置分页起始值、正数或负数步长，以及正整数的最大采集页数，不再限制为最多 500 页；支持 `2、3、4`、`2、4、6` 或 `100、99、98` 等变化规则。
- 可扫描 URL 中的数值参数并快速生成分页模板。
- 模板遇到无列表项、URL 重复、404/410、整页记录重复或达到最大页数时自动结束，并继续处理后续固定地址。

动态点击模式：

- 配置一个初始列表 URL，并点选页面中的“下一页”按钮。
- 每次点击后等待列表内容发生变化，再从最终渲染的 DOM 中采集数据。
- 页面内部接口无论返回 HTML、JSON 数组还是 JSON 对象，只要最终渲染出可选择的列表节点，就无需单独配置接口格式。
- 下一页按钮缺失或禁用、列表内容不变、整页记录重复或达到最大采集页数时自动结束，防止异常脚本造成无限翻页。

### 详情页采集

- 可关闭详情采集，只采集列表字段，并指定一个输出字段作为去重键。
- 启用详情后支持两种进入方式：
  - **读取链接**：从列表项、内部 `<a>`、列表项自身或最近的外层 `<a>` 读取 `href` 等属性。
  - **点击元素**：模拟点击没有 `href` 的列表元素，适用于前端路由或 JavaScript 事件打开详情的页面。
- 点击式详情会按列表顺序逐条打开详情并返回列表，确保详情数据与列表记录对应。
- 以完整 `URL.hostname` 判断站内与站外；hostname 相同才请求详情，不同 hostname 的外链不访问目标页面。
- 外链记录仍会输出，可将补全后的外链地址映射到任意模板字段；站内记录的“外链 URL”值为空。

### 字段采集与处理

每个 XML 字段或表格列都必须明确选择一种处理方式：

- 页面采集
- 固定值
- 系统值：当前列表 URL、当前详情 URL、ISO 格式采集时间
- 外链 URL
- 合并值
- 保留模板示例值
- 输出为空

模板字段较多且大部分无需采集时，可点击“全部设为输出为空”一次性将当前全部字段设为空，再单独配置需要采集的字段。

页面采集支持：

- 从列表页（相对于列表项）或详情页取值。
- 使用 CSS 或 XPath 1.0 选择器。
- 提取纯文字、保留 HTML 的内容或指定标签属性。
- 纯文字字段可填写“文字标签定位”，从同一节点中的“标签：值”内容里按标签提取对应值；标签后支持中文或英文冒号。
- 除 CSS 和 XPath 1.0 外，还可按页面 HTML 原文填写“内容前标记”和“内容后标记”，提取第一段或合并全部匹配段，并选择是否连同边界标记一起保存。原文匹配区分大小写，空格和缩进需一致。
- 文字和 HTML 字段可从常用标签预设中选择过滤项，也可手动输入 CSS 选择器；命中节点及其全部子内容会在取值前删除。
- 只取第一个匹配项，或按自定义分隔符合并全部匹配项。
- 去除首尾空白、合并连续空白、必填校验和有序字符串替换。
- 通过“验证”查看匹配数量和示例，通过“点选”生成选择器。

“合并值”可按顺序组合多个页面值、固定值、系统值和外链 URL，并配置统一分隔符。空子值会自动忽略，不会产生多余分隔符。

页面字段和“采集时间”系统值可独立开启“转为毫秒时间戳”。未开启的正文、标题及其他字段不会被改写；无法识别的日期输出为空，并在实时日志和 CSV 日志中记录字段、原始值与来源页面。

### XML 模板与导出

- 导入完整合法的 XML 模板，通过 XML 树选择一条示例记录节点。
- 保留模板中的固定节点、属性、注释、命名空间、示例值和声明编码。
- 支持普通嵌套字段和属性字段。
- 支持 `<field name="信息标题" id="title">...</field>` 这类重复 `field` 节点：使用 `id` 区分映射字段，同时显示 `name` 便于识别。
- 自动识别模板中每个字段原有的 CDATA，并可逐字段开启或关闭 `<![CDATA[...]]>` 包裹。
- CDATA 内容中出现 `]]>` 时会安全拆分，保持输出 XML 合法。
- 字段值中的 XML 1.0 非法控制字符会自动替换为空格，避免单条脏数据导致整个输出文件无法生成；HTML 标签结构不会因此改变。
- 每个 XML 文件最多保存 1–200 条记录，默认 200 条，超过后自动生成下一个文件。
- 写入时使用临时文件和原子重命名，降低中途退出造成不完整文件的风险。

### Excel 模板与导出

- 支持导入 `.xlsx` 和 `.xls` 模板。
- 兼容 WPS 生成的 `.xls` 模板；导出时会忽略 WPS 写入但旧版 XLS 格式不支持的内部属性。
- 使用首个工作表，第一行非空单元格作为可映射列，第二行起写入采集记录。
- 重复列名使用列字母区分并分别配置映射。
- 采集到的 HTML 作为普通字符串写入单元格，不解析为公式或特殊格式。
- 写入时沿用模板第二行对应列的单元格样式；模板首行和其他工作表会随工作簿一并输出。
- 输出格式与导入模板一致，同样按每文件 1–200 条记录自动拆分。

### 正文清理与资源处理

- HTML 字段可保留正文排版和标签，并移除 `script`、`noscript` 及其内容、注释、事件属性、危险脚本协议和 DocView 预览框。
- 字段级内容过滤先于资源处理执行，被过滤区块中的图片、视频和附件不会进入下载计划。
- 支持 `src`、`data-src`、`data-original`、`href`、`srcset`、行内样式 URL、`poster` 及用户补充的资源属性。
- “资源路径 URL 转码”默认关闭，已识别图片、音视频和附件路径中的中文文件名保持中文；开启后使用百分号编码，普通网页链接不受该开关影响。
- 只有已识别为资源的标签属性才参与资源绝对化、路径替换或本地化改写；正文中的普通链接、表单地址及其他非资源属性保持原值。
- 资源扩展名识别不区分大小写，但文件名保持原样；例如 `.PDF` 可正常识别，下载文件和改写后的资源链接仍使用 `.PDF`。
- 不下载资源时可选择：
  - 将资源地址绝对化后，按顺序执行字符串路径替换；
  - 使用“自定义前缀 + 原 URL 路径”直接改写站内资源地址。
- 可开启资源下载，将最终输出实际引用的站内图片、音频、视频和常见附件保存到指定目录。
- 图片或附件位于正文字段的 HTML 中时，其链接会在正文内同步改写，文件也会加入下载计划。
- 本地资源目录按原 URL 路径建立；同一路径带不同查询参数时会追加稳定短标识，避免文件互相覆盖。
- 资源只在所属页面的完整 hostname 相同时下载；站外资源保持原地址，站外重定向会终止该资源下载。
- 资源下载的开始、完成、跳过和失败日志会显示资源所在的列表页或详情页；下载失败同时写入 CSV 错误日志，但不会删除对应的输出记录。

### 检查点、日志与异常恢复

- 运行过程保存 JSON 检查点和 NDJSON 待写记录，可在暂停或异常退出后继续任务。
- 输出清单记录本任务生成的文件，覆盖模式只清理该任务清单内的旧产物。
- 错误信息写入 UTF-8 CSV，包含页码、列表序号、列表 URL、详情 URL、处理阶段、字段、原因、重试次数和时间。
- 详情请求并发可设置为 1–5；即使请求并发完成，最终输出仍保持列表顺序。
- 支持请求超时、请求延迟、自定义 User-Agent、自定义请求头，以及 UTF-8、GBK、GB2312、GB18030 编码覆盖。

### 关于与在线更新

- “关于与更新”弹窗显示当前版本、操作系统和 CPU 架构。
- 可在弹窗中开启“启动时自动检查更新”；开启后每次打开应用后台检查一次，发现适用新版时在顶部提示，点击即可进入更新弹窗。
- 自动检查默认关闭；关闭时只有用户手动点击才连接 GitHub Releases，自动检查失败也不会影响离线使用。
- 可显示 Release 标题、发布时间、更新内容简述及适用于当前平台的安装包大小。
- 正式安装版可下载对应架构的安装包，校验文件大小及 GitHub 提供的 SHA-256（如有），然后启动安装程序。
- 本地开发预览仅检查版本，不下载或启动安装包。

## 快速使用

1. 新建任务，填写任务名称和一条或多条列表页面 URL。
2. 打开列表预览，选择一条完整列表记录作为“列表项容器”，并验证匹配数量。
3. 选择静态 URL 分页或动态点击分页；需要分页时配置模板参数或下一页按钮。
4. 决定是否采集详情，并选择“读取链接”或“点击元素”。
5. 导入 XML、XLSX 或 XLS 模板，为每个字段或列选择处理方式并完成映射。
6. 配置正文清理、资源地址改写或资源下载，再选择采集输出目录和每文件记录数。
7. 执行测试采集，检查前 3 条数据、字段匹配数量、XML 预览和资源计划；需要验证实际文件时，点击“导出测试文件”另存为当前任务格式。
8. 保存草稿后开始正式采集，在运行中心查看进度、日志和输出结果。

任务名称决定最终输出目录：

```text
输出根目录/任务名称/
```

覆盖旧结果开启时：

```text
# XML 任务
任务名称_001.xml
任务名称_002.xml

# XLSX 任务（XLS 模板对应生成 .xls）
任务名称_001.xlsx
任务名称_002.xlsx

任务名称_错误日志.csv
```

覆盖旧结果关闭时，文件名会加入 `YYYYMMDD_HHmmss` 时间戳。

开启资源下载时，本地目录不包含 hostname，只镜像资源 URL 的路径：

```text
原地址：https://www.example.com/upload/2026/a.jpg
本地：资源根目录/upload/2026/a.jpg
写入地址：/resources/upload/2026/a.jpg
```

## 本地数据目录

配置统一保存在 Electron 用户数据目录下的 `collector-data`，与安装目录分离。覆盖安装或升级 TapCollect 时，安装器只替换程序文件，不会删除这里的任务配置。

常见位置如下；实际路径以操作系统和当前用户配置为准：

```text
Windows：%APPDATA%\TapCollect\collector-data
macOS：~/Library/Application Support/TapCollect/collector-data
Linux/UOS：~/.config/TapCollect/collector-data
```

```text
collector-data/
├── settings.json
├── tasks/<task-id>/task.json
├── checkpoints/<task-id>/checkpoint.json
├── checkpoints/<task-id>/pending.ndjson
└── manifests/<task-id>.json
```

旧版应用同级的 `data` 不会被自动读取、迁移或删除。需要继续使用其中的任务时，可通过任务管理菜单导出后再导入。

需要跨机器迁移任务时，使用任务管理菜单中的“导出全部任务配置”生成 JSON。导出的 `tasks` 数组可复制或调整后重新导入；导入的每个任务会分配新的本地 ID，不会覆盖现有任务。换到其他设备后，应重新核对输出目录和资源存放目录。

## 开发运行

建议使用 Node.js 22+ 和 npm 10+：

```powershell
npm install
npm run dev
```

开发服务器固定使用 `127.0.0.1:5677`。如果端口已被占用，释放该端口后重新运行；`strictPort` 会阻止开发服务静默切换到其他端口。

如果在中国网络环境中 Electron 二进制未自动下载，可执行：

```powershell
$env:ELECTRON_MIRROR='https://npmmirror.com/mirrors/electron/'
node node_modules/electron/install.js
npm run dev
```

正式版会隐藏 Electron 原生的 File、Edit、View、Window 菜单；本地开发预览会保留菜单，便于打开开发者工具和调试。

## 检查与本地验收

```powershell
npm run check
npm run build
```

`npm run check` 会依次执行 ESLint、TypeScript 类型检查和 Vitest。自动化测试只使用本地 HTML 和 `example.com` 占位地址，不访问真实采集站点。

如需对本机已经保存的真实任务执行单次冒烟验证，可把 `task.json` 路径作为参数传入。脚本会把输出改到临时目录，不修改原任务文件：

```powershell
npm run smoke:sample -- "$env:APPDATA\TapCollect\collector-data\tasks\<task-id>\task.json"
```

也可以设置 `TAPCOLLECT_SMOKE_TASK` 环境变量。真实 URL、选择器、模板、本地任务配置和采集输出均不会提交到仓库。

### 功能变更时同步文档

每次新增、调整、重命名或删除功能，都必须在同一任务中同步更新 `README.md` 和 `TapCollect使用说明-更新版.docx`。两份文档应以已经验证的实际行为和界面名称为准，并一并清理过时的说明、示例、常见问题、限制与版本信息。Word 使用说明修改后必须重新渲染并逐页检查；两份文档未同时完成同步时，功能变更不能视为完成。

## 本地打包

Windows x64 NSIS：

```powershell
npm run build:win
```

安装器依赖下载较慢时，可在当前 PowerShell 会话设置镜像后重试：

```powershell
$env:ELECTRON_MIRROR='https://npmmirror.com/mirrors/electron/'
$env:ELECTRON_BUILDER_BINARIES_MIRROR='https://npmmirror.com/mirrors/electron-builder-binaries/'
$env:CSC_IDENTITY_AUTO_DISCOVERY='false'
npm run build:win
```

UOS / Linux ARM64 DEB：

```bash
npm ci
npm run build:uos-arm64
```

macOS Intel 与 Apple Silicon：

```bash
npm ci
npm run build:mac:x64
npm run build:mac:arm64
```

macOS 安装包必须在 macOS 上构建。所有平台安装包默认输出到 `release/`，打包启用 ASAR、最高压缩，并只保留 `zh-CN` Electron 语言资源。

## GitHub Actions 与版本发布

- `CI`：推送到 `main` 或创建 Pull Request 时执行 lint、TypeScript 检查、测试和生产构建。
- `Package installers`：推送到 `main`、推送 `v*` 标签或手动触发时，构建 Windows x64、UOS/Linux ARM64、macOS x64 和 macOS ARM64 产物。
- 普通 `main` 推送和手动运行的安装包会上传到对应 Actions 运行页面的 **Artifacts**，默认保留 14 天。
- 推送 `v*` 标签时，工作流会等待全部平台构建成功，再自动创建或更新 GitHub Release 并上传 `.exe`、`.deb`、`.dmg` 和 `.zip`。

发布新版本前，先确保 `package.json` 中的版本号与 Git 标签一致，再推送标签，例如：

```powershell
git tag -a v0.4.8 -m "TapCollect v0.4.8"
git push origin v0.4.8
```

仓库的 `.gitignore` 已排除本地任务、检查点、运行清单、采集输出、导入模板、界面测试截图及开发工具状态目录。提交前仍应执行 `git status --short`，确认没有本地采集数据进入版本控制。

## 安全设计

- 主界面和远程网页实例均关闭 Node.js 集成，启用上下文隔离与 Electron 沙箱。
- 网页预览与动态采集实例拒绝权限请求和新窗口，远程页面不能直接访问本地采集 API。
- 静态任务通过主进程请求并解析 HTML；只有明确选择动态分页或点击式详情时，才使用独立隔离网页实例执行页面动作。
- URL 处理仅接受 HTTP/HTTPS，站内判断使用完整 hostname；外部详情和外部资源不会被误当作站内内容请求。
- 配置、检查点、输出和更新安装包均采用受控路径；任务配置和输出清单写入使用临时文件后原子替换。
- 在线更新只信任本项目的 GitHub Releases 页面与下载地址，正式安装前校验下载完整性。
